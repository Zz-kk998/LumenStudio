# 五分钟现场演示 / 录屏脚本

建议使用屏幕录制软件生成 `demo.mp4`，录制**实际双击打开的 Release 程序**，不要用 `python app.py` 的开发入口替代。若不使用真实模型 API，可说明离线演示验证工具执行和 GUI，但不能据此宣称验证了真实 LLM 的自由决策能力。

| 时间 | 操作 | 必须看见的证据 |
|---|---|---|
| 0:00–0:30 | 双击 `DesktopAgent`，观察标题栏与三栏 | 原生桌面窗口、文件树、编辑器、对话框 |
| 0:30–3:00 | 点击「离线演示」，在右侧工具 Trace 追踪 | `read`、首次失败的 `bash`、`edit` 精确匹配失败、二次修复、测试通过 |
| 3:00–4:00 | 查看 `notes/fix_log.md`，展示 MCP 结果 | `write` 保存文件、`mcp_demo_count_lines` 外部 server 调用 |
| 4:00–4:40 | 新任务并点击「停止」，或在终端演示 `python demo.py --mode interrupt` | 明确显示停止而不是转圈 |
| 4:40–5:00 | 讲一个最不满意的地方 | 例如：shell 尚未容器化，需要用户批准 |

**如果需要展示第三方真实 MCP**：修改配置并实现相应 client discovery 即可，但本仓库已经具备一个独立启动、真实 JSON-RPC 通信的外部 MCP 示例。

**建议现场回答的三个问题**：
1. `edit` 连续 10 次错误命中如何发现？——`count(old) != 1` 立即失败且不写回，Trace 中留证。
2. MCP 工具与内置工具怎么区分？——`mcp_demo_` 前缀经子进程执行 `tools/list` / `tools/call`，内置四工具直接路由 `Workspace`。
3. 为什么出错不会“沉默”？——把失败/退出码/超时送回模型，并通过右栏 Trace 标记。

完成录屏后，把 `demo.mp4` 放在项目根目录，检查画面清晰、能显示真实执行、时间符合老师要求。
